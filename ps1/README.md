# ps1/ — PlayStation platform layer

Copied from `RSDKv3-ps1/ps1/` at commit `1d1cd68` (2026-09-25; older notes cite `1e583ad`, the same commit before a
history rewrite), the finished Sonic CD port, and adapted freely for Sonic 2 and Sonic 1 (plans `../../docs/30`,
`../../docs/37`; what each piece taught: `../../docs/29`). Each file's header describes it in full; the Sonic CD /
Nexus notes in them still apply unless changed here. Sonic 1-only code sits behind `#if PS1_GAME == 1`.

| File | Role |
|---|---|
| `render.cpp` | the GPU renderer (from Sonic CD's, bound to v4): tiles from the packed chunk table, BG strips ('BGS2' / Sonic 1 'BGS3'), atlas sprites, Scene3D, fades |
| `gpu_chain.{cpp,hh}` | the per-frame DMA chain: per-parity arenas, bulk fragments linked with one `chain()` |
| `tileset.{cpp,hh}`, `sprite_atlas.{cpp,hh}` | stage-load VRAM uploads: tile pages and the per-character sprite atlases |
| `audio.cpp` | `RSDKv4/Audio.cpp` on the PS1: per-stage SFX banks on the SPU, CD-XA music |
| `menu.{cpp,hh}`, `menu_pack.h`, `menu_pack_s1.h` | the mobile menus' flow rebuilt in 2D; the packs' ids generated by `tools/menu/build_menu.py` (Sonic 2 / Sonic 1) |
| `cdrom_fs.cpp` | file I/O: the on-disc file index, the load stream, pinned files, stage-local copies |
| `cdrom_stream.{cpp,hh}` | continuous sector streaming (from Sonic CD); bounded close with abort (`../../docs/40`) |
| `xa_music.{cpp,hh}` | CD-XA music; bounded waits with abort (`../../docs/40`) |
| `spu.{cpp,hh}` | SPU driver on the ps1-bare-metal model |
| `mdec.{cpp,hh}`, `video.{cpp,hh}` | MDEC + STR player carried over from Sonic CD (built; the mobile data has no FMV) |
| `fmv.{cpp,hh}` | Sonic CD's full-screen FMV layer, kept in the folder but not in the Makefile's `SRCS` |
| `irq_guard.{cpp,hh}` | lost-IRQ guard for psyqo's I_STAT acknowledge, stale CD latches and orphan CD answers (`../../docs/31`, `40`) |
| `loading.{cpp,hh}`, `loading_icon.h`, `loading_icon_s1.h` | the loading indicator; the icons are generated (see below) |
| `memcard.{cpp,hh}`, `memcard_icons.h` | memory card saves (slot 1); icons generated by `tools/memcard/build_icons.py` |
| `memcard_test.cpp` | memory card self-test (`make MEMCARD_TEST=1`) |
| `pc_sampler.cpp` | PC sampler for profiles (`make SAMPLER=1`, `tools/pc_profile.sh`) |
| `combo_test.cpp` | 1-up + Sign Post / Super test without a debugger (`make BOOT=<stage> COMBO=1\|2 [GAP=n]`; dist refuses it) |
| `platform_test.cpp` | the phase 0 smoke test (`make PLATFORM_TEST=1`, `tools/smoke_test.sh`), reading Sonic 2 files |
| `libc/` | our libc / C++ header shims |

Differences from the Sonic CD copy:
- `loading_icon.h` is generated from `PS1/Memcard icons/sonic-2-loading.gif` by
  `tools/loading/build_icon.py`: the first 144×144 cell of each GIF frame (8 distinct poses), reduced to
  48×48 cells, least-used colours merged to 15 + transparent, 30 ms/frame. `loading_icon_s1.h` (Sonic 1) comes from
  `sonic-1-loading.gif` (4 frames). Line 1 of each names its source. Credit: the public builders list the icons as
  fan-made pixel art, author unknown (the Sonic CD builder credits `sonic-1-loading.gif` to Salmon270 on Tenor).
- `memcard_icons.h` (regenerated identically by `tools/memcard/build_icons.py`) holds `s_ps1McIconSonic2` from
  `2-mc-icon.png` (both games' save icon).
